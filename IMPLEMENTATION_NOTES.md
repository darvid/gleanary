# Infactory MVP implementation

## Baseline and decisions

- Specification read from `/Users/david/Development/infactory/SPEC.md`; it is absent from this linked worktree. No main-checkout files are modified.
- macOS 26+, Swift 6.2, SwiftUI/Observation, GRDB 7.11.1. Both SwiftPM and an explicit-file Xcode project exist.
- `DocumentStore` is the canonical SQLite actor. Notes/revisions, captures/source identities, content blocks and content-addressed originals already exist. FTS5, NaturalLanguage embeddings, source-cited Apple summaries, graph and mind map features are retained.
- Baseline: `swift test` builds and reports 128 tests passing; native-generation, live-network and large-performance tests are opt-in/skipped. FoundationModels deprecation warnings pre-exist.
- New authored artifacts remain ordinary revisioned notes. A source–note association table enables multiple-source syntheses without a duplicate note or search system.
- Conversation, tasks/events, JD taxonomy/memberships and link proposals use additive migrations. Foreign keys cascade associations, not canonical notes. Existing source/capture data is not rewritten.
- Chat captures retain readable source content before asking for inference. Failure/unavailability must not prevent saving or browsing a source. The incumbent summary-first capture workflow is unchanged.
- One bounded coordinator uses application-owned tools; model output cannot execute SQL, mutate existing notes or approve proposals. Each generation has its own session. Source excerpts remain untrusted data.
- UI extends the incumbent native typography and library/preview conventions. `#general` becomes the landing surface; Library/Graph/Mind Map remain reachable. No aesthetic interview is needed: the user explicitly requested autonomous implementation and the spec pins the native chat composition.

## Migration and recovery

New tables are additive and each migration is transactional. Do not downgrade schema in place. To roll back an application version, quit Infactory and restore a prior complete SQLite backup (use SQLite's backup API or copy the database plus WAL/SHM while no process is using it), preserving the adjacent artifacts directory. No automatic reset or destructive conversion is introduced. Interrupted conversation tasks are marked failed/retryable on reopen, never succeeded.

## Optional cloud boundary

Verified OpenAI's official `https://developers.openai.com/siwc/token-sharing-open-source` registration, sessions, inference and preview-limitations documentation on 2026-10-12. The user confirmed open-source distribution and requested ChatGPT integration. Optional native OAuth is now implemented; on-device remains default. An eligible account and user-controlled browser sign-in are still required for live verification. No private ChatGPT endpoints, client secret, API key or deployed backend are used. Choose an open-source license before distributing the app; this change does not choose one on the user's behalf.

`ChatGPTSession` handles dynamic registration, saved account/workspace registrations, fresh state/nonce/PKCE, issued-client reuse, validated RS256 identity, granted plan scopes, serialized refresh, account-switch fences and sign-out/revocation. `OAuthLoopback` binds only `127.0.0.1` on an available port at `/auth/callback`, starts before the system browser, and rejects unrelated state. Credentials are stored together in the macOS Keychain, device-only and non-synchronizing; never in the library database, preferences, diagnostics or source control. A non-secret host ID and account-specific source-sharing preferences live in UserDefaults. Refresh serialization is within the running app; concurrent independent Infactory processes sharing the same Keychain record are not supported.

`ChatGPTConnection` and settings expose saved accounts, account-specific models, cancellation, sign-out, plan-usage disclosure and a separate explicit sharing toggle. Source-grounded research sends the question, bounded titles and at most five selected excerpts from each of up to four sources to public `https://api.openai.com/v1/responses`. It uses stateless `store: false`, `stream: true` requests, strict structured output and a second evidence-verification request. That second request also uses the plan. Ordinary chat sends the current message and at most 12 recent messages, with per-message bounds, in one streamed request. Invalid/incomplete output is not published, and errors never silently fall back to Apple. Remote research discloses excerpt coverage rather than claiming whole-document review. Library's incumbent capture/graph inference remains local; the provider selection affects new #general messages.

## Known limits and deliberate scope

- ChatGPT OAuth/provider code is shipped but **live account sign-in and inference are not verified**. Browser sign-in, eligible plan entitlement and user consent cannot be replaced by credential-free tests. No genuine account credentials were used during implementation.
- Dispatch and category defaults are deliberately small deterministic policies, not an unrestricted autonomous agent framework. A mention identifies a tool-owning role, not a permanently running persona.
- Comparison claims are grounded in a **selected excerpt set**, disclosed in the saved artifact, not a full-paper comparative review. Source-grounding checks reduce, but do not prove the absence of, model errors.
- Retrieval uses the existing text/semantic engine; conversational date phrases such as “last week” are not structured date filters. Use source selection for exact comparisons. One URL is accepted per message; multiple URLs produce an actionable error.
- Metadata-only YouTube capture retains a known canonical link when no authorized transcript exists and explicitly declines content research. Existing social-browser/audio recovery remains in Library; no unauthorized transcript service was added.
- Link proposals are the implemented reviewable mutation; arbitrary agent-authored edits/merges/deletions are not exposed. Category moves are explicit user UI actions and can be reversed by selecting the previous home.
- No user-study or external GUI/VoiceOver validation is claimed. Performance evidence is the live/test timings above and durable task/event timestamps, not fabricated product metrics.
- The existing Markdown renderer supports headings, unordered lists, fenced code and inline formatting/links; it is not a complete CommonMark renderer.
